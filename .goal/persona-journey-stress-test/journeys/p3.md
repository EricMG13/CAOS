## Attempt to make the gate rubber-stamp

The persona's core objective is adversarial: get a committee-ready verdict out of
evidence that does not deserve one. The p1 stack had produced the ideal test
subject — run `456fbaa2`, built from a single scanned PDF yielding **0 chunks**
and **0 extractable text**, with no LLM key configured.

If the gate were a rubber stamp, this run is what it would stamp.

It did not:

```
qa_status: Restricted            committee_status: Restricted
findings_by_severity: CRITICAL 0 · MATERIAL 4 · MINOR 2
model_id: "fixture"              input_snapshot_state: "unapproved"
```

The gate independently flagged the two failure modes that matter here:

- **QA-001 / QA-002** — *"could not be resolved to an ingested source chunk"* —
  it caught that claims had no evidence behind them, which is precisely the
  condition a 0-chunk ingest creates.
- **QA-003 / QA-004** — weak lineage and *conflicting* lineage between a senior
  facilities agreement and an indenture.

The LLM never self-declared committee-ready; `gate.py` supplied the verdict and
the run stayed Restricted. **I5 PASS — the attack failed.**

`committee_export_allowed` was never satisfied, so no export could be forced out
of a Restricted run. Report Studio's export gate was therefore never reachable
to test directly — recorded as untested rather than passed.

## I10 — stress legs

**Back/forward through the wizard:**

```
before   /upload?context=c8225724…&issuer=BCULC
goBack   /upload?context=c8225724…&issuer=BCULC   (same URL — no exit)
goForward /upload?context=540f72e3…               (different context, issuer param gone)
```

Back does not leave the page, and forward lands on a different context id with
`issuer` dropped. My first reading was per-navigation context churn; querying
both databases disproved it — contexts are **one per surface and reused** (p1: 5
contexts / 5 surfaces; p3: identical), so the forward navigation resolved to the
surface's own "Document intake" context rather than minting a new one.
→ **W-03 withdrawn.** The residue is F-01's parameter drop, already charged.

**Not exercised:** concurrent runs, refresh mid-ingest, double-submit on
finalize, and two personas contending over one issuer. The last is structurally
impossible as configured — each persona holds an isolated database, so no shared
issuer exists. Recorded as untested.
